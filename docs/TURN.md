# TURN-сервер: свой у каждого

## Зачем он нужен

Видео идёт напрямую между устройствами. Чтобы соединиться, им сначала нужно узнать свои внешние адреса: это делает бесплатный STUN (Google), он уже встроен.

Прямое соединение невозможно, если хотя бы одно устройство находится:
- в **мобильном интернете** (операторский NAT),
- в сети с «строгим» NAT или корпоративным файрволом.

Тогда нужен **TURN**: сервер-посредник, который пересылает видео между устройствами. В CamerasController нет общего TURN-сервера: каждый пользователь подключает **свой**, и видео не идёт через чужие машины.

**Если все камеры и клиент дома в одной Wi-Fi-сети, TURN не нужен.**

## Вариант А: статический TURN (проще всего)

Подходит любой провайдер, который выдаёт постоянные логин и пароль.

| Провайдер | Бесплатно | Где взять данные |
|---|---|---|
| [ExpressTURN](https://www.expressturn.com/) | бесплатный личный тариф | личный кабинет после регистрации |
| [Metered](https://www.metered.ca/stun-turn) | 0,5 ГБ/мес (20 ГБ с картой) | Dashboard → TURN Server → Credentials |
| свой `coturn` на VPS | — | см. документацию coturn |

1. Зарегистрируйтесь и скопируйте из кабинета адрес сервера, логин (username) и пароль (credential).
2. При создании сети в клиенте раскройте **TURN-сервер** и вставьте в поле **«статические TURN-серверы (JSON)»**, например:

```json
[
  { "urls": "turn:free.expressturn.com:3478", "username": "ВАШ_ЛОГИН", "credential": "ВАШ_ПАРОЛЬ" },
  { "urls": "turn:free.expressturn.com:3478?transport=tcp", "username": "ВАШ_ЛОГИН", "credential": "ВАШ_ПАРОЛЬ" }
]
```

Если провайдер даёт вариант `turns:…:443?transport=tcp` (TLS на порту 443), обязательно добавьте и его: через мобильных операторов чаще всего проходит именно он.

## Вариант Б: Cloudflare Realtime TURN (надёжнее, 1000 ГБ/мес бесплатно)

У Cloudflare TURN-ключи временные, поэтому их выдаёт маленький воркер из этого репозитория (`packages/turn-worker`). Сам API-токен остаётся в секретах Cloudflare и в приложения не попадает.

1. Зарегистрируйтесь на <https://dash.cloudflare.com>.
2. **Realtime → TURN Server → Create TURN key**. Сохраните **Key ID** и **API Token**: токен показывается только один раз.
3. Установите [Node.js](https://nodejs.org) и выполните в папке `packages/turn-worker`:

   ```
   npm install
   npx wrangler login
   npx wrangler secret put TURN_KEY_ID           # вставьте Key ID
   npx wrangler secret put TURN_KEY_API_TOKEN    # вставьте API Token
   npx wrangler secret put ALLOWED_NETWORK_ID    # ID сети (см. ниже)
   npx wrangler deploy
   ```

4. `wrangler deploy` выведет адрес вида `https://cc-turn.<ваш-поддомен>.workers.dev`.
5. При создании сети вставьте этот адрес в поле **«Адрес TURN-воркера Cloudflare»**.

**Где взять `ALLOWED_NETWORK_ID`:** на экране «Создать новую сеть» в Windows-клиенте, в разделе TURN, заранее показан **ID будущей сети**. Скопируйте его в секрет, разверните воркер и только потом нажмите «Создать сеть». Воркер выдаёт ключи только этому ID, поэтому чужие не смогут тратить ваш лимит. Если сетей несколько, перечислите ID через запятую.

## Если сеть уже создана без TURN

TURN-настройки входят в код приглашения. Чтобы их добавить: отключите клиент от сети, создайте новую сеть с TURN (тот же Firebase-конфиг подходит) и подключите устройства новым кодом.
